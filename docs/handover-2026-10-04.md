## Entscheidung: React-Bits-Originale nur privat (Weg 2)

Die Svelte-Portierungen von React-Bits-Komponenten (Copyright 2026 David Haz, „MIT + Commons Clause“,
https://github.com/DavidHDev/react-bits) liegen **nicht** im öffentlichen Repo. Erlaubt ist die Nutzung als Teil einer
Anwendung. Verboten ist, die Komponenten selbst „allein, im Bündel oder als portierte Version“ weiterzugeben. Ob öffentlicher
Quelltext darunter fällt, ist nicht geklärt (keine Rechtsberatung). Deshalb gilt:

- **Öffentlich (`iap`)**: nur die eigenen Nachbauten, voll funktionsfähig.
- **Privat**: die Originale samt Anpassern liegen im privaten Repo `usbaidrive` unter `iap-overlay/` (dort steht eine
  `README.md` mit der Anleitung). Beim Bauen wird der Ordner nach `app/src/private/` kopiert. Er ist in `.gitignore`.
- **Mechanismus**: Ein kleines Vite-Plugin (`privateOverlay` in `app/vite.config.ts`) nimmt, wenn unter
  `app/src/private/<Pfad>` eine Datei liegt, diese statt der öffentlichen mit demselben relativen Pfad. Ohne den
  Ordner ändert sich nichts. `@app` ist ein Alias für `app/src`, damit private Dateien öffentliche Module importieren können.
  `svelte-check` prüft `src/private` nicht (`exclude` in `tsconfig.json`).
- **Geprüft**: Build ohne Overlay (kein Original-Code im Bündel) und mit Overlay (Originale im Bündel) laufen beide durch.
  Die Oberfläche mit Overlay habe ich nicht im Fenster angesehen.
- **Nicht im Overlay**: die Regler-Dämpfung in `PromptBar` (öffentlich linear statt sigmoid) und das Zeigerlicht
  (`pointerGlow`, eigene Umsetzung). Die Optik weicht dort minimal von früher ab.
- **Wenn David Haz zustimmt**, kann man die Originale direkt ins öffentliche Repo holen (Lizenztext
  `licenses/react-bits-LICENSE.md`, Zeile in `THIRD-PARTY-NOTICES.md`, README-Hinweis, Herkunftskommentare; alles liegt in
  `usbaidrive`). Bis dahin nichts davon veröffentlichen.

## Offene Punkte (unverändert oder neu)

- **GitHub-Rechte:** Die Claude-GitHub-App hat inzwischen Schreibrechte auf `iap` (Push klappte). Der Auto-Modus
  blockiert Veröffentlichungen in öffentliche Repos teils trotz Zustimmung; ein erneuter Versuch nach ausdrücklicher
  Bestätigung ging durch.
- **Name „IAP“:** Nicht auf Marken oder Namenskollisionen geprüft (in der Software-Welt steht „IAP“ oft für
  „In-App-Purchase“). Als Arbeitsname okay.
- **Logo:** Herkunft und Rechte am Logo (Stern mit Dreieck) sind nicht geklärt.
- **Tests:** Ein App-Test schlägt unter Linux fehl, weil er einen Windows-Pfad prüft (CI läuft auf Windows).
  Windows und das echte Pet-Fenster sind nicht neu getestet.
- **Wortmarke und Effekte** sind im Browser mit Mock-Daten gesehen worden, nicht im echten Tauri-Fenster.
- **Quelle im Modellkatalog** ist nur Text, nicht klickbar (IAP öffnet bewusst keine externen Links). Ein
  Kopieren-Knopf wäre möglich.

## Befehle zum Prüfen

```
# im Wurzelordner des Repos
node app/scripts/gen-third-party-notices.mjs --check
node app/scripts/check-clean-repo.mjs      # nichts Persönliches im Repo
cargo fmt --all && cargo test --workspace
# im Ordner app
npm ci && npm run check                    # Svelte und TypeScript
node scripts/i18n-keys.mjs --missing       # Übersetzungen vollständig?
npm run build && cd src-tauri && cargo check   # braucht ../dist, sonst bricht tauri::generate_context! ab
```

Die Tauri-App (`app/src-tauri`) gehört **nicht** zum Cargo-Workspace des Wurzelordners (`members = ["crates/*"]`),
`cargo check -p portable-ai-app` im Wurzelordner funktioniert deshalb nicht. Im Ordner `app/src-tauri` ausführen.
